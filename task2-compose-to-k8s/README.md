# Task 2 – Docker Compose to Kubernetes

Flask + Redis hit-counter from the Docker Compose getting-started tutorial.
`app.py` was modified to print the pod hostname so load balancing is visible.

## Files
- `app.py`, `requirements.txt`, `Dockerfile` – application source.
- `compose.yaml` – modified compose file.
- `k8s/` – manifests generated by Kompose (then edited).

## Compose changes
```yaml
services:
  web:
    image: abdulsalam78976/flask-redis-app:1.0   # (a) build: . replaced by published image
    restart: always                              # (b) restart policy
    ports: ["8000:5000"]
  redis:
    image: redis:alpine
    ports: ["6379:6379"]                         # (c) redis ports defined
```

## Steps
```bash
# Install kompose
curl -L https://github.com/kubernetes/kompose/releases/download/v1.35.0/kompose-linux-amd64 -o kompose
chmod +x kompose && sudo mv kompose /usr/local/bin/

# Build and publish the image (Docker Hub user names must be lower-case)
docker build -t abdulsalam78976/flask-redis-app:1.0 .
docker login
docker push abdulsalam78976/flask-redis-app:1.0

# Convert, edit, deploy
kompose convert -f compose.yaml -o k8s/
sed -i 's/replicas: 1/replicas: 3/' k8s/web-deployment.yaml
sed -i '/spec:/a \  type: NodePort' k8s/web-service.yaml
kubectl apply -f k8s/
kubectl get pods -o wide                # -> outputs/t2-pods.txt

# Load balancing
for i in $(seq 1 10); do curl -s http://$(minikube ip):32758; done   # -> outputs/t2-loadbalance.txt
```

## Generated resources
| File | Kind | Purpose |
|---|---|---|
| `web-deployment.yaml` | Deployment | Runs the Flask container (port 5000), `restartPolicy: Always` from `restart: always`. Edited to `replicas: 3`. |
| `web-service.yaml` | Service | Maps compose `8000:5000` to `port: 8000 → targetPort: 5000`. Edited to `type: NodePort` (node port 32758). |
| `redis-deployment.yaml` | Deployment | Single Redis pod, containerPort 6379. |
| `redis-service.yaml` | Service (ClusterIP) | Gives Redis the DNS name `redis`, which `app.py` uses as host. |

Kompose adds `io.kompose.service` labels (used by selectors) and `kompose.*` annotations recording the command/version.

## Result
Responses alternated between pods `web-76df9d7c88-w8qgm` and `web-76df9d7c88-d7566` while the
counter kept increasing 1→10, showing that kube-proxy spreads requests over the replicas and
all replicas share state through the single Redis service.

## Docker Compose vs Kubernetes
| | Docker Compose | Kubernetes |
|---|---|---|
| Scope | Single host | Cluster of nodes |
| Scaling | `--scale`, no built-in LB on a fixed host port | `replicas`, Service load-balances |
| Self-healing | `restart:` policy only on the same host | Controllers recreate pods, reschedule on other nodes |
| Networking | Bridge network, service-name DNS | Cluster DNS, ClusterIP/NodePort/Ingress |
| Config | One `compose.yaml` | Many declarative objects (Deployment, Service, …) |
| Build | Can `build:` locally | Needs a pushed image from a registry |

## Issues met
1. `docker push Abdulsalam78976/...` → `lookup Abdulsalam78976: no such host`. Docker treated the
   capitalised first path segment as a registry hostname. Fixed by re-tagging with the lower-case
   name `abdulsalam78976/flask-redis-app:1.0`.
2. `docker compose up` → `Bind for 127.0.0.1:8000 failed: port is already allocated`; `curl` returned an
   Apache 403 page. A host Apache server already used port 8000. Fix: stop the conflicting service
   (`sudo systemctl stop httpd`) or change the host port mapping.
